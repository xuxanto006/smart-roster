## 算法改动要点（踩过的坑）

1. `tryPlan(slots, N, R)`：强制休息日先占位并计入 dayRest 配额；noOff/only 的日子从休息日候选中剔除；only 固定班在分层填班前预排（这样早/晚班的互斥检查能自动避开它）；canTake 加 ruleOK；修复阶段加 `movable()` 防止挪走固定班/请假，策略5 跳过 forcedOff。
2. **周末晚班缺 1 人的结构性 bug**：周末需求 12 > 工作日 10，且周末当天人力零冗余（24 岗 = 24 人）。原贪心让工作日晚班吃到富余人次，周末晚班被「周六晚→周日早」互斥挤掉。修法两条：填班日序改为按需求降序（需求大的先填）；修复阶段新增**策略1b「同日富余班次改班」**（某班次超过需求时，直接把那人改到缺口班次，无需找人补位）。这一条是让 25 条规则场景从 21/25 提到 25/25 的关键。
3. 「微调」的容量守恒：某人被强制休息后，必须把他原本的休息日改成「待排」，否则团队总人力凭空少一天、必然留缺口。`fillGaps` 新增**②b 挪休息日**（把当天休息的人调来上班，同时把他另一个「有富余」的工作日改成休息，仍保 2 天休），以及 ④ 兜底 allowOverfill（会使人只休 1 天，结果里明确提示）。
4. 保险：autoSchedule 结束再跑一次 `fillGaps(w, R, false)` 补贪心残留缺口（禁用 allowOverfill 以保证每人恰好休 2 天）。

## 四轮迭代：31 人真实名单 + 占位自动迁移

- 用户上传 32 人名单 JPEG（图里实际只列了 31 人），要求把 32 个「员工01…员工32」占位替换为真实姓名。
- 改动最小化（用户特意叮嘱「只在人员管理里面替换名字，其它不需要改动」）：

  ```js
  const DEFAULT_STAFF = ["何广友","邓臻蓝","孙勇",…,"田方斌"];  // 31 个
  const isPlaceholderName = n => /^员工\d+$/.test(n);
  // 初始化：
  if(state.staff.length===0) state.staff = DEFAULT_STAFF.slice();
  else if(state.staff.every(isPlaceholderName)){
    state.staff = DEFAULT_STAFF.slice();
    Object.values(state.schedule).forEach(w=>{
      Object.keys(w).forEach(n=>{ if(!state.staff.includes(n)) delete w[n]; });
    });
    state.requests = state.requests.filter(r=> state.staff.includes(r.name));
    save();
    __migratedFromPlaceholders = true;  // 触发一次性 toast
  }
  ```

- 关键设计：占位迁移用 `state.staff.every(isPlaceholderName)` 判定，**只在全员都是占位时才迁移**——一旦用户已经填了真实姓名，绝不覆盖。
- 没有顺手加「内联改名」/「批量替换 textarea」——用户明确说其它不动。改名诉求（持久化）以「占位迁移 + 提醒『可在人员管理修改』」回应。
