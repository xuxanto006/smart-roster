## 本轮（进行中，用户叫停「下次再调整」）：冲突定位 —— 状态卡可点击跳到冲突格

需求（截图反馈）：工作台「本周状态 / N 处冲突 / 班表已填 X%」→ **变为可点击链接，查看冲突的点在哪里**。

### 已实现（仅本地 `app_merged.html`，**未同步 _deploy / 未发布**）
1. 定位标记：排班表 `<tr>` 加 `data-row-name`；每个 `.shift-cell`（含经理/免排/暂免格）加 `data-name`+`data-day`；表头 `th.day-head` 加 `data-day`。
2. CSS：`.hstatus.conflict-link`、`.check.link`、`.metric.link`（cursor+hover）与 `@keyframes conflictFlash` / `.conflict-flash`（红圈闪烁 2 次）。
3. 新增 4 个函数（插在 `const STAFF_LEVELS` 之前）：
   - `locateConflict(msg)`：从冲突文案里解析 `{name, day}`——姓名取名册里出现且最长者（防「张三」误配「张三丰」），星期取文案中最先出现的「周X」。
   - `flashEl(el)`：加闪烁 class + `scrollIntoView`，2.8s 后移除。
   - `focusConflict(spot)`：优先「人名+星期」定位到格子 → 退化为整行（`.name-cell`）→ 再退化为该天表头 `th.day-head`。
   - `gotoConflict(i)`：`switchView("schedule")` → 闪烁定位；定位不到就滚到 `#schedChecks` 提示条并 toast 文案。
4. 工作台接线：`renderDash` 新增 `hasIssue`；状态卡加 `conflict-link`+`onclick="gotoConflict(0)"`；每条 ⚠ 提示 chip 加 `.link`+`onclick="gotoConflict(idx)"`（errs 在前、warns 在后，索引对齐 `errs.length+i`）；「规则冲突」指标卡可点。
   `renderDashChecks`（排班页顶端提示条）同样加了可点链接。
5. `lastHealth` 三处赋值都补上 `all: errs.concat(warns)`（含初始声明），供 `gotoConflict` 按索引取文案。

### 设计取舍（下次可改）
- 采用**解析冲突文案**定位，而非把 `renderHealth` 的 `errs` 改成结构化数组：改动小、不动体检逻辑。
  代价：「缺人」这类**无具体人**的冲突只能定位到那一列的表头；配置类冲突（人力不够/上限卡死/分组产能）无定位点，退化为滚到提示条。
- 若要求「每处冲突都精确落格」，需把 `renderHealth` 里约 13 处 `errs.push` 改成带 `{name,day}` 的结构化记录（较大重构）。
