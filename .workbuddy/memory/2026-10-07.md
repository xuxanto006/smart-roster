## 请假类型改造：「必须休息（请假）」→「必须请假」+ 新增「必须off」

用户截图指出下拉框，要求改文案 + 加一个 off 选项。

### 语义定义（本轮定下的关键区分）
| 类型 | value | 强制休息 | 标记请假 | 占请假额度 | 格子显示 |
|---|---|---|---|---|---|
| **必须请假** | `off` | ✅ | ✅ | ✅ | **假**（`shift-cell rest leave`） |
| **必须off** | `offday`（新增） | ✅ | ❌ | ❌ | **休**（`shift-cell rest`） |

理由：两者都要求「这天不排班」，但只有请假有假期类型、会扣额度、要在格子里标「假」。
`offday` 走排班口径的普通休息，不碰请假体系。

### 改了 9 处
1. **HTML 下拉**（L1291）：`必须休息（请假）`→`必须请假`；新增 `<option value="offday">必须off</option>`
2. **数据字典注释**（L1537）：补 `offday 必须off`
3. **`TYPE_LABEL`**（L1543）：`off:"必须请假"`，新增 `offday:"必须off"`
   ⚠️ **关键**：`TYPE_LABEL` 同时是**存档白名单**（L2512 `state.requests.filter(r=>TYPE_LABEL[r.type])`），
   不加进去请求会被静默丢弃。
4. **规则初始化**（L2660）：`{off, offDay, noOff, only, ban}`
5. **`buildRules`**（L2666）：`offday → c.off=true; c.offDay=true`
   —— 调度内核只认 `c.off`，所以 offday 复用全部排班逻辑，一行算法没改
6. **`ruleText`**（L2687）：offday 显示「必须off」，off 显示「必须休息（请假）」
7. **`conflictTypes`**（L2731）：`norm(t)= t==="offday"?"off":t` 归一化，两者冲突语义等价；
   额外加 `off vs off` 互斥（原先靠 `same` 去重兜住）
8. **粘贴识别**（L2775）：`TYPE_PATTERNS` 在「请假」**之前**插 `{type:"offday", re:/必须\s*off|强制\s*off|^off$/i}`
   —— 顺序关键，否则「必须off」会被「休息/不上班」抢走
9. **格子渲染**（L5787）：`isLeave = c.off && !c.offDay && v==="rest"`；另 CSV 导出（L6650）区分为 `"off"` / `"请假"`

`updateLeaveRow()` 无需改：`isOff = type.value === "off"` 天然让 offday 不显示假期类型行。

### 验证
- 新建 `test_offday.js`：**30/30 通过**（覆盖白名单/标签/编译/文案/互斥/排班结果/格子 class 与文字/粘贴识别/假期类型行显隐）

  `test_health` `test_roles` `test_roster` `test_request` `test_mustwork` `test_day_needs`
  `test_paste` `test_paste_real` `test_dated_req`
- `hunt_locked.js` 120 轮：锁定事项 0 违反
- 已发布 409,259 字节，curl 核对与本地源逐字节一致；线上实测 `off=必须请假` / `offday=必须off`

### 踩坑（都是我自己测试的 bug，程序没问题）
1. `pushRequest(nm, day, type, scope, **weekKey**, date, leaveType)` —— 第 5 参是 weekKey 不是 leaveType，

   `EXCLUDE_MODULES.has(p.module) || EXCLUDE_POSITIONS.has(p.position)`。

3. 悬停提示按情况区分：`该岗位暂时不参与排班` vs `该模块暂时不参与排班`。

## 17:15 · 鸿蒙智行独立排班系统（排班「领域」机制）

### 设计
新增「领域」维度 `state.domain`（`"3c"` / `"hongmeng"`）。周数据 `state.schedule[weekKey][name]`
本来就是按人存的，所以两套班表天然共存；**需求 / 规则 / 表格 / 可排班名单各自独立**。

| | 3C顾问 | 鸿蒙智行 |
|---|---|---|
| 人员 | 61 人（可排班 44） | 19 人（可排班 16，3 经理除外） |

| 班次上限 | `state.limits` | `state.limitsHM` |
| 休息配额 | `state.restMax` | `state.restMaxHM` |

### 关键改动（10 处）
1. `EXCLUDE_MODULES` 移除「鸿蒙智行」——它不再靠"排除"实现，改由领域隔离。
2. 新增领域工具：`HM_MODULE` / `DOMAINS` / `curDomain` / `isHongmeng` / `inDomain` /
   `domainStaff` / `domainSchedulable` / `domNeeds` / `domLimits` / `domRestMax` / `withDomain`。
3. **`autoSchedule(dom)`**：入口先把 `state.domain = dom`（否则内部 helper 走 `curDomain()`
   拿到另一个领域的规则表 → `R[i]` undefined 崩溃，浏览器实测过）；人员按领域裁剪；
   **`state.schedule[k]` 由「整周覆盖」改为 `Object.assign` 合并**（否则鸿蒙智行排班会抹掉 3C 班表）；
   手工标记只清本领域；开店闭店角色跳过鸿蒙智行（否则清空 3C 已分配的角色）。
4. **`repatchWeek(silent, dom)`** 同样处理 + `reqs` 按领域过滤。
5. `buildRules(weekK, dom)`：只给当前领域建规则表 → 请假/固定班天然不串领域。
6. `renderTable`：人员循环、表尾「实际/需求」「当日休息人数」全部按领域 + 读 `domNeeds(DOM)`。
7. `setDayNeed`：写进**当前领域**的需求（否则鸿蒙视图改需求会污染 3C）。
8. `renderHealth(week, R, dom)`：10 处 `state.staff`/`state.needs` 换成 `DOMSTAFF`/`NEEDS`；
   **开店闭店 / 早晚保障检查限定 `DOM === "3c"`**（这两组是 3C 专属概念，在鸿蒙视图会报无关告警）。
9. `confirmSchedule` / `scheduleExportRows(dom)`：导出只含当前领域，文件名带领域名。
10. UI：`#domainTabs` 两个页签（带各领域可排班人数）+ `switchDomain()` / `renderDomainTabs()`；
    存档 `snapshotState` 与 `load` 补 `needsHM/limitsHM/restMaxHM/domain`。

- **初始需求不能贴着容量上限**：16 人 × 5 天 = 80 人次容量，我最初设 79 → 可行性处在临界，
