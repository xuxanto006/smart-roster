用户要求：① 在需求里加「月度需求」（如这个月总共休几天）② 加月度排休导出按钮。

### ① 需求面板加月度汇总行
在 `renderSchedNeeds()` 里新增 `#schedNeedsMonth`，5 个格子：
本月天数 / 月需求人次 / 月人均上班 / **人均月休** / **全组月休**
口径：`月需求 = 一周总人次 × ceil(当月天数/7)`；
`人均月休 = 当月天数 - 人均月上班天数`。
用户要的「这个月总共休几天」=人均月休 / 全组月休两格。

### ② 新增 exportMonthRest() —— 月度排休表
与 exportCSV（整月班表）分工：
- exportCSV：每天一格，写班次
- exportMonthRest：每人一行，统计休息/早/中/晚/请假/出勤率 + 末尾全组汇总

只剩 `return csv` —— 点「下载排班表」毫无反应。
教训：重写一个「生成 + 下载」的函数时，**下载那一行要一起带走**。

## 追加：批量排多周（18:30）

用户从「延展清单」里只选了这项。目标：一次排好接下来 N 周，省得一周一周点。

### 实现要点
**核心思路**：临时把 `currentMonday`往后挪一周，调用**同一个** `autoSchedule()`，排完挪回去。
算法完全复用 —— 不存在「批量版算法」与「单周版算法」结果不一致的问题。

三个关键设计：
1. **公平性**：第2周起把上周班表**错开一天**铺成初稿（复用 `copyPrevWeek` 的思路），
   算法只补缺口不动已有格子 → 休息日自然轮转。否则每周从零开始，很可能连着几周都挑同一个人休。
2. **静默**：`const BATCH = {on, quiet}`。`toast()` 与 `renderAll()` 开头判断 `BATCH.quiet` 就 return。
   renderAll 是全量重渲染，N 周排下来会明显卡，而且中途 currentMonday 被移动、渲出来的是中间周。
3. **回滚**：批量前 `JSON.stringify({schedule, roles, roleSig, manual})` 快照，
   任何一周抛错整体还原，不留半成品。

UI：`#batchMask` 对话框（毛玻璃遮罩 + 2/4/6/8/12 周单选 + 「覆盖已有排班」勾选），
按钮放在「一键智能排班」右侧。

实测：4 周全部排好，每周 160 班次 / 64 休息，完全一致（公平轮转生效）。

### 踩的坑（都是「插错位置」类）
1. JS 插到了 HTML 区域（`id="toast"` 后面）→ 成了页面文本，`openBatchDialog is not defined`。
2. 修第一次时用「找注释行 → 找下一个 batch-mask」切片，**多切了 700 多行 HTML**（把容器也剪了）。
3. 对话框 `<div class="batch-mask">` 插到了 `<div class="toast">` **内部** —— toast 是个 34×22 的提示条元素，
   `position:fixed` 被它裁掉，对话框只剩 34px 宽（截图上完全看不见）。
   → 移到 `</body>` 之前，成为 BODY 直属子元素。

**教训**：在这个文件里插入代码时，锚点必须选**语义明确且唯一**的字符串。
用「下一个同类标记」当结束锚点太脆弱 —— 嵌套结构一变就会切多/切少。
插完必须验证：语法 + 注释配平 + 花括号配平 + **浏览器实测**。
