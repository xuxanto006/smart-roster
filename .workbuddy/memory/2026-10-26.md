## 追加：修「整月班表导出全是未安排」（17:15）

用户反馈「导出的排班表格里没有显示」。这其实是**上个月做月班表导出时就埋下的 bug**，
不是李敏改动引起的（李敏那行确实在导出里，只是格子内容为空）。

### 根因：`weekKeyOf` 有一个隐含前提
```js
function weekKeyOf(mon){ return fmt(mon); }   // 假定参数已经是「周一」
```
导出时算当月每一天对应的周 key：
```js
const wkey = weekKeyOf(o.date);   // ❌ o.date 是某一天，不是周一
```
结果 10月1日→key=`2026-10-01`、10月2日→key=`2026-10-02`……
**每一天都被当成独立的一周**，`getWeek(wkey)` 全部取不到数据 → 整片「未安排」。

**修法**：`weekKeyOf(mondayOf(o.date))`（项目里已有 `mondayOf()` 做「回退到周一」）。

**通用教训**：
> `weekKeyOf` / `curKey` 这类函数名里带 key 的，**几乎都隐含「参数必须是周首」**。
> 传别的东西不会报错，只会静默取不到数据 —— 症状是「一片空白/未安排」，
> 极易被误判成「没数据」或「改了没生效」。

### 验证
李敏在 10月26日那周的导出结果（修后）：
```
10/26 早班 · 10/27 晚班(闭店) · 10/28 中班 · 10/29 休息 · 10/30 晚班(闭店) · 10/31 晚班
统计：休息2 早1 中0 晚3 周末1  ← 与格子完全吻合
```
本月其他周显示「未安排」是**正常的**（系统按周排，其它周本来就没排）。

测试：导出 17/17 · 专项 81/81

## 追加：营业时间段统一（17:35）

用户给出标准营业时间表：
```

晚班1 13:00–22:00 │ 晚班2 13:30–22:30 │ 闭店 14:00–23:30
```

**发现**：统计页的 `SHIFT_TIME_ROWS` **早就是这 6 段、时间完全一致**，
但排班页的**图例**和**点格子下拉**各写各的（晚班写 13:00–22:30，没有分档）。

**改动（按确认的方案：只统一显示，不真的拆成两个班次）**
1. 新增 `SHIFT_TIME` 常量 —— 各班次时间的**唯一来源**，以后别再各写各的
2. 排班页图例：晚 → **晚1 13:00–22:00 / 晚2 13:30–22:30** 两项
3. 点格子下拉：晚班项改成 `.opt-slots` 结构，两档时间竖排右对齐
4. **导出时自动分配晚班1/2**：按当天该部门的晚班人数均分，
   人数少的一半写「晚班1」，多的写「晚班2」

### ⚠️ 踩坑：计数器建错作用域
晚班1/2 的分配要靠「当天晚班序号」，我把 `nightSeq` 建在**每个人的循环内部** ——
结果每人都是 idx=0，全部写成「晚班1」，晚班2 出现 0 次。
**计数器必须建在人员循环外面**（部门级共享），同一天里第 1 个人是晚1、第 2 个是晚2。

**通用教训**：「按名次/序号分配档位」的逻辑，计数器的作用域 = 分配的分组范围。
放错一层 → 全员并列第一。

修复后实测：晚班1 38 次 · 晚班2 30 次 · 纯「晚班」0 次（仅统计列标题）
