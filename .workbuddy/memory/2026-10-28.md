## P1 · 账号中心「人员」页（本日第二轮，未提交时的内容见提交记录）

用户需求来自规划文档「人员管理重构」：人员新增/编辑、绑定账号、改角色、解绑。

**关键调查（决定了实现路线）**：
- `staff` 表的 RLS：`pol_staff_read` → `is_active_user()`；`pol_staff_write` → `is_editor()`（manager/viewer）→ **经理可直接 REST 写 `staff`**，不用新增后端。
- `profiles` 前端**完全不可写**（`pol_profiles_read` 只给 select）→ 绑定/改角色/解绑必须走 `review` Edge Function（service_role）。
- `review approve` 的 `staff_name` 传空会**回落到 `target.staff_name`** → 它只能绑/换绑，**永远解不开**。所以新增 `unbind` 动作，否则「解绑」做不出来。
- 前一轮线上把 `test` 接到 `谢佳委` 上，正是因为没有解绑能力才没绑 `黎振鹏`。这条新动作以后能解开这类死结。

**前端**（`_deploy/view-account.html`，一个页面加 3 块）：`人员` 页签 + 人员列表（统计 / 搜索 / 部门 / 在职筛选）、员工资料弹层 `#stDlg`、绑定账号弹层 `#bdDlg`。

| 能力 | 调用 | 备注 |
|---|---|---|
| 名单 / 筛选 | `SR.db.select('staff', 'select=name,module,position,level,domain,active,joined_at,left_at,note&order=active.desc,name.asc')` | 只要经理权限 |
| 账号绑定关系 | `SR.db.select('profiles', 'select=…&status=eq.active')` | 只读，用来算「在职未绑账号」 |
| 新增 / 改资料 | `SR.db.insert/patch('staff', …)` | patch **刻意不带 `name`** |
| 离职 / 复职 | `patch` `{active:false, left_at:今天}` / `{active:true, left_at:null}` | 只动名单，不断登录 |
| 绑定 / 改角色 | `api('review', {action:'approve', id, staff_name, role, display_name})` | 必须显式带 `display_name`，否则会被员工名覆盖 |
